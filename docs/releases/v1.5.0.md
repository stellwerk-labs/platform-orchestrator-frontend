# Console v1.5.0

## Module Drafts

Create a Draft, edit it, and save each reviewed revision. If another author
changes the stored revision, reload the Draft before continuing; stale edits are
rejected. Capture a saved revision explicitly for one Environment. Capture does
not deploy. Select the captured snapshot and choose **Run captured test** to
execute it with a deployment manifest. Later Draft edits leave earlier captures
and test deployments unchanged.

Publishing closes the Draft and freezes the exact reviewed revision as a
separate immutable Proposed Module Version. It does not make that Version
Default or deploy it. Making a Version Default remains a separate explicit
action. Existing Module Versions and Pins remain unchanged.

## Resource Type interfaces

Review interface history and publish the exact next consecutive interface
version. New Module Versions can select a specific interface version;
publishing a later interface does not change existing Module Versions or Pins.
Older HTTP callers that omit the interface version continue to select version 1.

## Compatibility

The Console uses generated TypeScript clients. Use matching server APIs and
gateway routes. Existing HTTP operations remain available. An unavailable Draft
test endpoint reports an error. The Console never substitutes an ordinary
deployment or another Module Version.
