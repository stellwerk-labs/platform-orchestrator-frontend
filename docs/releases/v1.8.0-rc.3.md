# Console 1.8.0-rc.3

Project pipelines can be authored in the designer or as JSON/YAML documents, validated, saved as drafts and explicitly published as immutable versions. The designer exposes direct Apply or reviewed Plan/Apply, supported catalogue steps, optional cost estimation and conditional cost approval. The server validates the same contract used by the API, octl and Provider.

Project policy controls allowed versions and independent forward and rollback defaults. With policy off, direct Apply remains the default and a Plan runs only when requested explicitly. Deployment creation can select an exact published version, subject to current server policy and Runner compatibility.

Deployment details show Plan and Apply changes, approval and cost evidence, task outcomes and phase-specific execution logs. A stale Plan can be replanned instead of reused. The view distinguishes infrastructure already applied from a pipeline left unsettled by a post-Apply failure, and presents supported controls without treating an unknown outcome as permission to rerun Apply.

Native Runner registration supports form and code views against the canonical public registration contract. The server-issued UUID and approved execution catalogue identify the site; saving registration does not activate it.

Protected log views retain permission checks and exclude log content from browser persistence and session replay. Use the coordinated Core, Data Plane, IAM and Runner candidates for these features and follow the Native deployment prerequisites before enabling a site.

For self-hosted Console, set `RUNNER_ROLLOUTS=true` on the Console container to enable the pipeline UI.
