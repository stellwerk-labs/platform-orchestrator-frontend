# Console v1.4.0-rc.4

This release candidate adds the Environment deployment queue to the UI and a
sandboxed host for first-party plugin pages at contract level `v1alpha`. It is
intended for evaluation and testing before the stable release.

## What changes

- Environment status shows queued Deployments with position, mode, requester,
  age, expiry and transient promotion errors. Holders of `deployment_write` can
  cancel an item. Items queued with `halt_on_failure` are marked, and an item
  rejected with `previous_deployment_failed` names the failed Deployment and
  links to it.
- A fenced Environment shows which plugin-dispatched Deployment fenced it and
  since when. "Acknowledge outcome" appears only when the fence exists, the
  caller holds `deployment.outcome.acknowledge` and `remedy_available_at` has
  passed; a reason is required. The action becomes available without a page
  reload even when the browser delays rendering until after that time.
- Plugin pages run in sandboxed cross-origin iframes. The host brokers only
  allowlisted Orchestrator operations, never passes Console cookies or tokens,
  and rejects malformed idempotency keys. Declarative contextual actions,
  protected Deployment material and availability notices are supported.
- Platform operators who hold the IAM platform permission `plugin_manager_read`
  get a read-only "Plugin Manager" view (navigation entry and
  `/platform/plugins`). It lists plugin installations with package version and
  digest, state, organisation mode (`selected` or `all`), enabled organisations,
  licence summary (installation grant state and organisation limit) and
  capability registration problems. An installation page shows each enabled
  organisation with state, timezone, capability registration and covering grant,
  pending organisations, the installation grant, packages and recent audit
  events. Nobody else sees the entry, and the URL shows an access denied page.
  The view changes nothing.
- A banner shows plugin licence grace warnings.
- Scoped role rows are keyed by membership identity.
- The image producer builds browser assets on the builder's native platform
  instead of repeating JavaScript compilation under target-platform emulation.
  The Nginx runtime and its checksum-bound packages remain target-specific for
  amd64 and arm64. Both independent no-cache builds, content scans, licence
  checks and reproducibility comparison remain required.

The RC2 producer stopped at its 300-second first-build limit while compiling
the arm64 browser bundle. Its failed run and signed source/tag remain immutable;
this build-stage correction does not retroactively qualify RC2 or establish a
DNS fault, Vite defect or other unproved underlying cause. Each successor requires its own
artifact qualification and human publication review.

## Release metadata correction

The image producer pins Buildx 0.38.0 and disables only its auxiliary GitHub
Actions event-context capture when creating the builder. Maximum BuildKit
provenance, SPDX SBOMs, explicit source/workflow/run provenance, signatures,
strict content scans and protected human publication review remain required.
No emitted attestation is rewritten and no scanner exception is added.

RC3's original first image build completed, then its original-content inspection
step failed. The retained log does not identify the underlying validation rule;
the failed RC3 source/tag/run remain immutable. The builder-context correction
addresses a demonstrated metadata/scanner conflict, not proof of the sole hosted
failure or a retroactive RC3 qualification. RC4 needs its own complete gates.

## Compatibility and upgrade

Test this candidate with CP 3.1.0-rc.2, DP 4.0.0-rc.2 and IAM 2.5.0-rc.3. The
compatible candidate set is still undergoing qualification; this is a prerelease
for evaluation, not a stable release.

The Plugin Manager view needs the CP Plugin Manager read endpoints and the IAM
platform check (`resource: platform`). With a Control Plane that lacks plugin
discovery, unknown organisation routes show "Plugin discovery failed" instead of
the 404 page.

## Known limitations

The Console image ships no Content Security Policy of its own; the chart's CSP
and the plugin runtime's UI CSP restrict plugin origins. Serve plugin UIs from a
separate registrable domain: sibling subdomains are same-site. The Console
Plugin Manager is read-only; installation and package changes remain operator
actions.
