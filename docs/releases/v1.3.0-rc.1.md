# Console v1.3.0-rc.1

This release candidate exposes Module Version Management in the Orchestrator UI.

## What changes

- Inspect catalogue entries, version history, immutable definitions, lifecycle
  events and adoption before deciding what to publish or promote.
- Compare two versions with concrete before/after values, including inputs,
  parameters, dependencies, provider mappings and output declarations.
- Create complete Proposed versions, explicitly promote stable versions and
  inspect restricted lifecycle actions according to the caller's permissions.
- Inspect and manage exact Environment Pins, bulk operations and Pin notes.
- Distinguish denied history access from an empty version list.
- Make the packaged Nginx configuration readable by the unprivileged image user.

## Compatibility and upgrade

Use CP 3.0.0-rc.1, DP 3.2.0-rc.1 and IAM 2.4.0-rc.1. Updating only the Console
does not update the server schema or public API contract.

Catalogue-read and version-read permissions are separate. Review custom roles
if users can find a Module but cannot inspect its versions. Disabled or hidden
actions are not a substitute for server-side authorization.

Publication creates Proposed versions rather than editing a mutable definition.
Promotion changes future Default resolution; it does not itself deploy
infrastructure. Archive and teardown retain immutable version history.

This prerelease must be checked with the compatible server and Runner set.
It does not update the stable Console image or deployment automatically.
